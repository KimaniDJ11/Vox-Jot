## Gemini review adjudication

A read-only CLI review using `gemini-3.8-flash-high` returned findings. It did not run the tests or install the app. Findings were checked independently:

- **Fixed:** legitimate silence longer than 60 seconds must not look like a corrupt audio clock. Storage now permits long gaps; the regression includes 70 seconds. A separate future-clock check remains.
- **Hardened, not measured:** increased the callback queue to 256 packets with a 16,000-sample packet cap, at most approximately 16 MiB of sample storage. This is not evidence of zero dropped audio under actual disk stalls.
- **Fixed:** failed native startup releases outputs and drains callbacks instead of waiting on a stop of an unstarted stream; capture-status/drain errors retain a path to finalization; interrupted partials are recovered even if metadata already says interrupted; new transcription invalidates stale summary availability.
- **Rejected after a native probe:** `AVAudioPCMBuffer(bufferListNoCopy:)` did not produce an empty frame length. The local SDK probe wrapped 480 frames and reported 480 frames/capacity.
- **Rejected:** meeting transcription does not write learned personal-dictionary corrections; the cited path reads the dictionary.
- **Rejected as missing context:** application quit already waits for the meeting worker's finalization signal.
- **Kept deliberately:** a requested system-audio capture with no system frames is incomplete, even if microphone audio exists. Saved audio is retained; microphone-only success must not be represented as system capture.
