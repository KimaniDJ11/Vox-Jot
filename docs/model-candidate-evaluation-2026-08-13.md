# Model Candidate Gate Evaluation — 2026-08-13

## Outcome

The supplied candidate list is useful, but it is not safe to translate directly into Model Hub rows. It mixes genuinely promising releases with non-commercial weights, cloud-only services, duplicate/currently implemented models, incomplete OCR components, and models whose official runtime does not work on Vox Jot's macOS path.

The strongest next candidates are:

1. **IBM Granite 4.0 1B Speech** for an Apple-silicon STT prototype through its documented MLX Audio path.
2. **Inflect Micro v2 ONNX** and **Audio8 TTS Preview ONNX INT4** as small, local TTS prototypes.
3. **Qwen3.5 0.8B/2B GGUF** and **Granite 4.0 Micro GGUF** for the full 46-case Refine benchmark before any recommendation.
4. **PP-OCRv6 medium detection + recognition as a pair**, after extending the existing PaddleOCR adapter beyond v5.
5. **DeepFilterNet3 Core ML** as a runtime-size and startup-latency experiment, not as a new cleanup model.

No candidate in the supplied list is ready to become a ranked or user-visible row today without more work. The closest is Granite 4.0 1B Speech, but it still needs a canonical app ID, managed artifact path, installed-app transcription test, and the complete STT benchmark.

## Important corrections to the source list

- [Audio8-ASR-0.1B](https://huggingface.co/Audio8/Audio8-ASR-0.1B) is itself **CC-BY-NC-4.0**, not merely restricted in an ANE conversion. Its end-to-end checkpoint is approximately 324M parameters; “0.1B” describes only part of the architecture. It is unsuitable for Vox Jot production distribution without separate commercial rights.
- [CrisperWhisper2.0 Large](https://huggingface.co/nyralabs/CrisperWhisper2.0_large) is also explicitly non-commercial/research-only.
- [pyannote Precision-2](https://huggingface.co/pyannote/speaker-diarization-precision-2) is a small pipeline descriptor for a service that uploads audio to pyannoteAI. It is not a local open-weight diarization model.
- Vox Jot already uses **DeepFilterNet3** through `init_df()` in `src-tauri/resources/python/denoise_sidecar.py`. The MLX/Core ML repositories are alternative runtimes for the same model family, not a quality-model upgrade.
- **Qwen3-4B-Instruct-2507** is already in Vox Jot's verified LLM collection and ranked data. Its completed 46-case result was rank 25, 15/46 cases passed, warm p50 4,484 ms, and warm p95 5,927 ms. It is not a catalog gap and should not be duplicated.
- **ACE-Step 1.5** already has repository integration and evaluation artifacts, but it is intentionally absent from the user-facing creative-audio catalog because the normal app path has not been completed and validated.
- Local MLX copies of **DeepSeek-OCR** and **DeepSeek-OCR-2** already exist in app support. Direct load probes with the shipped OCR runtime failed because the processor/tokenizer stack is not recognized. Downloaded is therefore not equivalent to runnable.
- **PP-OCRv6 medium detection** is only the detector. A usable OCR option also requires the matching recognition model and an adapter change; Vox Jot's current PaddleOCR loader is wired to v5 names.

## Evaluation method and status language

Each candidate was checked against:

- the current Rust/TypeScript model catalogs and aliases;
- model download and provider code, including the actual backend boundary;
- existing full-suite result files and evaluation scripts;
- live Hugging Face metadata, repository contents, revisions, licenses, gated state, and official runtime instructions;
- the installed app-support runtimes and model directories on this Mac;
- direct loader probes where a candidate was already downloaded locally.

Status terms are deliberately distinct:

- **Metadata verified**: the live repository identity, revision, files, and license were checked.
- **Static path found**: matching code or a provider exists, but execution was not proven.
- **Load-probed**: the installed runtime attempted to instantiate the local model.
- **Full-suite tested**: the relevant complete Vox Jot benchmark exists. Smoke tests are not treated as ranked evidence.
- **User-visible ready**: the normal installed-app path, app-managed artifacts, errors, and complete benchmark have all passed. None of the new candidates reaches this state yet.

No multi-gigabyte weights were downloaded and no ranked data, catalogs, or user-visible controls were changed during this evaluation. Doing so before a working managed runtime would create misleading availability. The external model drive was not mounted, and no hosted/local artifact was changed, so drive or Hugging Face synchronization was not applicable.

## Recommended execution order

1. **Granite 4.0 1B Speech:** create one canonical STT ID, pin the official or verified MLX artifact, validate it against the app's pinned MLX Audio runtime, then run the complete STT corpus and installed-app microphone-to-paste flow.
2. **Refine tournament:** download only Q4_K_M artifacts for Qwen3.5 0.8B, Qwen3.5 2B, Granite 4.0 Micro, then SmolLM3 3B and conditional LFM2.5 2.6B; run all 46 cases and add numeric ranks for every completed model.
3. **Small TTS prototypes:** implement Inflect ONNX first, then Audio8 ONNX INT4. Validate voice discovery/preset/preview through the catalog, not only direct scripts, and run the complete TTS suite with ASR round-trip scoring.
4. **OCR repair before expansion:** implement the missing DeepSeek MLX processor bridge or remove/mark the existing local artifacts as blocked; separately add PP-OCRv6 detection+recognition support and run all six OCR cases.
5. **Cleanup backend comparison:** make Core ML an offline/opt-in experimental backend, measure it against current DeepFilterNet3 and RNNoise, and keep it out of the live dictation hot path until parity is proven.
6. **Finish existing creative work:** decide ACE-Step's incomplete app path before adding another large creative runtime. Stable Audio 3 Medium comes after access/license and runtime feasibility are resolved.

## Verification boundary

This is a complete **pre-integration gate evaluation**, not a claim that every viable model has completed a performance benchmark. A legitimate Vox Jot full benchmark requires a functioning app-managed provider and the complete category suite; candidates without that path cannot be ranked honestly. Existing full-suite evidence was reused where it already exists, and direct installed-runtime load failures were recorded rather than hidden.

Because this work changes only documentation, recording/transcription/post-processing/paste paths are untouched and user-visible latency is unchanged. Any future candidate implementation must report cold and warm installed-app measurements separately; model-card speed claims are not accepted as Vox Jot end-to-end latency evidence.
